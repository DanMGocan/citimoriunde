# Biblioteca Comunității

Romanian-first community coordination for physical books. Owners retain their books until handover; each approved city is a shared catalogue, not a staffed library. The neutral app label and URL are configured through `.env`. Developer/operator communication is English; interface and service emails are Romanian.

The application is a modular Next.js/TypeScript monolith with PostgreSQL, Better Auth, bounded Sharp uploads and a durable PostgreSQL worker. See `IMPLEMENTATION_PLAN.md`, `PROGRESS.md`, `TEST_REPORT.md` for actual implementation/check status. Do not interpret this README or a build as certification that every acceptance scenario has passed.

## Admin bootstrap

No default admin password, fabricated auth user, or unverified-email elevation exists. `.env` reserves `ADMIN_BOOTSTRAP_EMAIL=gocandan@gmail.com` for one local operator command only. Production profile onboarding requires published policies, so initial legal publication is a protected local operator step before the first admin exists:

```sh
# Export drafts into a NEW directory; existing reviewed files are never overwritten.
npm run legal:export -- /absolute/new-review-directory
# Have all eight texts reviewed, complete actual operator/processor/retention/legal details,
# and replace draft markers only after that review. Configure real operator/contact
# values and LEGAL_REVIEWED=true in protected .env. Keep registration disabled.
npm run legal:bootstrap -- /absolute/new-review-directory --confirm-reviewed
```

This appends all eight published database versions and an audit record in one transaction. It refuses unchanged draft markers, incomplete files, prior publication or existing administrators. The flag is the operator's review attestation; it does not assert legal approval by the application or agent. After initial setup, administrators publish later versions through the audited admin workflow.

Configure real Google OAuth, sign in through Google, accept the actual published terms and adult/profile declaration, enrol and verify TOTP in account settings, then:

```sh
npm run admin:bootstrap
# Compose alternative after the same real account prerequisites:
docker compose run --rm web npm run admin:bootstrap
```

Local email signup requires the adult/terms declarations on the server and records the three current policy versions only for a genuinely created account; duplicate-email responses never alter an existing profile or acceptance history. Email verification still gates lending, messaging and other restricted actions. Google accounts accept policies and declare adulthood separately in profile onboarding.

The command checks verified provider account + active adult member + verified TOTP, promotes transactionally once, and audits the action. Production admin actions also require a session-scoped fresh TOTP step-up. Roles and moderator scopes are server enforced. After bootstrap, normal audited admin role controls manage changes; rerunning bootstrap cannot promote another account.

## Backup, restart and updates

```sh
npx tsx scripts/backup.ts --compose
npx tsx scripts/restore-test.ts /absolute/path/to/backup --compose
# Native private PostgreSQL alternative: omit --compose.
# Restart configured services without dropping data:
docker compose restart web worker
# After reviewed source/dependency changes, build once then migrate/recreate:
docker compose stop web worker
docker compose build web
docker compose run --rm web npm run migrate
docker compose up -d --force-recreate web worker
```

The stop/build/migrate sequence above is for Compose and represents a maintenance window. The current native preview is managed through [its separate systemd units](ops/NATIVE_RUNTIME.md). Stop after a failed command: a failed build leaves services stopped until you explicitly restart the preserved previous image, and a failed migration needs review before restarting code. Keep a known working image tag and tested backup before updating. Never use `down -v` for an update.

Back up before an update and validate restoration into a separate database. The `--compose` drill uses the database container's PostgreSQL client and private socket; it needs neither a published database port nor host PostgreSQL tools. It validates image archive paths/types before writing into a separate protected temporary directory. It creates/drops only its generated database after successful creation, and performs bounded count/photo checks before reporting success. Native isolated database/image restoration has passed; Compose restoration and real offsite recovery remain unverified. Add the production override flags when managing a Compose proxy. Preserve the previous image and snapshot for recovery; do not reset Git or remove volumes. [BACKUPS.md](BACKUPS.md) explains consistency, off-server destination and safe recovery. [CONFIGURATION.md](CONFIGURATION.md) lists settings. [GO_LIVE_CHECKLIST.md](GO_LIVE_CHECKLIST.md) distinguishes external/operator blockers from application health.
