Its actual fields include `LocID`, `City_Code`, `City_Name`, `PWCent_Longitude`, `PWCent_Latitude`, and annual columns 1975–2050. The extractor uses header names rather than guessed column offsets.

The workbook's `info` sheet confirms populations of harmonised DEGURBA cities with at least 50,000 inhabitants, at mid-year, **in thousands**. Its geographic columns are **population-weighted centroids in decimal degrees**. Values for **2025 (1 July)** are converted to integer persons by decimal half-up rounding. Blank 2025 cells belong to cities that have no published estimate for that reference year, including places reaching the threshold later; the extractor excludes them rather than treating them as zero. These are harmonised urban-centre estimates, not administrative city-proper or metropolitan populations. [Official demographic glossary](https://population.un.org/wup/glossary-demographic-terms).

Changes made here are geographic filtering, conversion/rounding, ranking and Romanian display names/aliases. They do not imply UN endorsement.

## Geographic treatment

The current product scope is **European Union member countries**, verified on **2026-10-09** against the official [EU country directory](https://european-union.europa.eu/principles-countries-history/eu-countries_en) and [its second page](https://european-union.europa.eu/principles-countries-history/eu-countries_en?page=1). `data/eu-countries.json` contains the 27 allowed ISO country codes and the corresponding UN M49 source identifiers. The extractor and domain services use this shared policy. EU membership admits Cyprus and excludes countries such as the United Kingdom, Russia, Türkiye, Ukraine, Serbia, Norway and Switzerland, regardless of continental or Schengen classifications.

The original 50-city geographic-Europe manifest contained **32 EU cities**. The redesign retains those source IDs and adds **Cluj-Napoca, Iași and Timișoara** as explicitly requested. It does not fill the removed places with unrelated replacement cities. `data/geography-review.json` records the 32 retained and three added stable IDs. Earlier continental-boundary decisions remain in that file as historical evidence; they no longer govern admission and cannot restore a non-EU city.

The new manifest contains **35 distinct cities**, ranks 1–35 in descending 2025 source population. The requested additions use actual cells from the same checked-in UN snapshot:

Centroids do not identify library premises or member addresses. These are online communities, with no physical-premises assumption.

## Existing-database upgrade

`migrations/009_eu_city_scope.sql` deactivates non-EU libraries and clears their initial rank. It preserves their IDs, member references, copies, requests, loans and historical records. The database constraint `libraries_active_eu_country` prevents later activation of a non-EU library, so existing public queries and lifecycle checks based on `active` inherit the eligibility rule. Library listing also explicitly filters EU codes; new locality requests, approvals and linked destinations require EU eligibility. Historical non-EU requests can still be rejected and reviewed.

The migration inserts the three requested Romanian cities from sourced values, reuses an existing canonical/display/alias match when present, and updates the 35 initial ranks. Existing administrator labels, active states and IDs are retained; an existing Romanian record receives its stable source ID, aliases and verified source metadata. A conflicting existing source identifier stops the migration for review instead of merging unrelated records. Repeating the migration does not add duplicate cities. Run the normal migration command before the new seed or deploying the redesigned app; existing applied migration files are unchanged by this geography update.

## Reproduction and checks

Inspect the checked-in snapshot:

```bash
python3 scripts/extract-cities.py --inspect
sha256sum data/snapshots/WUP2025-F21-DEGURBA-Cities_Pop.xlsx
```

Reproduce the manifest without network access:

```bash
python3 scripts/extract-cities.py --retrieval-date 2026-10-09
python3 scripts/extract-cities.py --self-test
```

`--fetch` downloads only the documented official URL, checks that it is an XLSX archive, bounds the compressed/decoded input, and refuses to overwrite a snapshot. To inspect a newly retrieved source independently, pass a new destination and record its real retrieval date; review any source changes before replacing the checked-in snapshot or city selection.

The updated extractor's **11 synthetic checks** cover source-header aliases, rounding, coordinate validation, blank reference-year cells, explicit city selection, non-EU exclusion and Cyprus eligibility. Synthetic fixtures never write the production manifest or supply its populations. Focused unit tests cover shared EU-code consistency, the 35-city source selection, aliases, and rejection of altered/non-EU seed data. Isolated PostgreSQL regression tests cover migration reruns and canonical reuse, preservation of historical references, stale non-EU approvals, and database eligibility enforcement. Actual database/build/browser execution results are recorded separately by the integration owner in `PROGRESS.md` and `TEST_REPORT.md`.

`scripts/seed.ts` validates the EU selection, source snapshot checksum, city count, order, ranks, identifiers, coordinate ranges and consistent provenance before insertion:

```bash
npm run migrate
npm run seed
```

Stable source identifiers and `ON CONFLICT DO NOTHING` preserve administrator changes and avoid duplicate libraries on seed reruns. The seed publishes no fake member/book/loan data. Forum categories are application content; policy documents remain drafts until explicitly published. Source verification does not assert public-launch readiness.
